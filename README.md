# RemoveRedundantSig

A MuseScore 3 plugin that deletes redundant time signatures without messing up the layout. It accomplishes this by editing the mscz file itself and then re-opening the file. This is the only workaround that ensures the rest of the score is kept completely intact.

Requires MuseScore 3.5+ (developed and tested on 3.6.2).

## Installation

1. Copy `RemoveRedundantSig.qml` into your plugins folder
   (`Documents/MuseScore3/Plugins` by default).
2. `Edit → Plugins → Plugin Manager`, tick **RemoveRedundantSig**.

## Usage

The plugin has three modes, chosen by what is selected when you run
`Plugins → RemoveRedundantSig`:

**Remove one signature** — click the redundant time signature, then run the plugin. It verifies the signature restates the prevailing meter, refuses anything else, and removes it. Courtesy signatures at line ends are generated at layout time and never stored in the file, so the plugin cannot affect them.

**Clean up the whole score** — run the plugin with *nothing* selected. It removes every stored signature that is *fully* redundant. A signature is removed only if **all** of the following hold:

* its numerator, denominator, display style (common-time **C** vs numeric 4/4 vs cut time), and any custom text matches the prevailing signature (so a numeric `4/4` following **C** is kept: removing it would change the engraving);
* it is not the first signature of the piece;
* it is not in the measure immediately after a **section break** (restating the meter at a movement start is correct notation);
* an identical redundant signature exists in **every** staff at the same measure — which also means local/per-staff time signatures are never touched.

Anything not removed is listed in the plugin console with the reason. To manually remove a redundant sig not meeting the criteria, simply select the sig and run the plugin (only the nominal meter is checked in this case).

**Undo** — run the plugin with nothing selected *when nothing has changed since the last time the plugin ran*. (You'll be offered 3 options: Undo / Clean Up / Cancel).

## The problem

See [musescore#21578]: https://github.com/musescore/MuseScore/issues/21578

In MuseScore 3 (fixed in Musescore 4), deleting a mid-score time signature triggers a measure-rewrite ("rebar") across the span up to the next time signature — **even when the deleted signature restates the prevailing meter and nothing about the barring actually changes.** The measures in that span are destroyed and rebuilt as objects, and everything attached to them goes down with the rebuild:

* manual **system/page/section breaks** are removed;
* **volta segments** are regenerated at default position, discarding any
  manual offsets;
* spacers and stretch in the span are likewise lost.

## Safety model

* The plugin **auto-saves** before operating. For .mscx it additionally verifies that the serialized score matches the file on disk (guarding against failed saves and external modification, e.g. cloud-sync surprises) and aborts on mismatch.
* Before every operation, a backup is written to MuseScore's own hidden backup folder: `.mscbackup/<name>.rrs.bak` (for .mscz files this contains the pre-operation .mscx serialization).
* A post-operation snapshot (`.mscbackup/<name>.rrs.post.mscx`) is kept as the undo-eligibility oracle and consumed on undo.
* The plugin closes and reopens your tab as part of the operation (for .mscz, a temporary tab also flickers by — this is normal). The undo history is lost in the process; this is a MuseScore limitation, and is exactly what the integrated Undo mode compensates for.
